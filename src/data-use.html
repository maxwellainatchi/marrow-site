Plain answers to the questions health systems and app reviewers ask about how Marrow uses data from Epic.

Who is the developer?

Maxwell Ainatchi, an individual developer. Marrow is a personal, non-commercial project. It has no investors, no advertising and no paid plans. Contact: {{CONTACT}}.

Who uses the app?

Patients, for their own records. Marrow is a patient-facing app; it is not used by clinicians or health systems.

What data does it read?

Only the FHIR resources the patient approves at sign-in, read-only: patient demographics, conditions, allergies, medications, immunizations, observations (labs and vitals), procedures, encounters, care team and documents. Marrow never writes to Epic.

Where does the data go?

To the patient's own Marrow server and nowhere else. The OAuth exchange happens on that server, which is a confidential client; access and refresh tokens are stored there encrypted and never reach the browser. The developer does not operate a central server and never receives patient data.

Is data sold or shared?

No. Data is never sold, never used for advertising, never shared with data brokers, and never sent to a cloud AI service. Any AI features run on a local model on the patient's own server.

Can the patient get their data out, or delete it?

Yes. The patient can export or delete everything from Marrow, and revoke Marrow's access from MyChart at any time.

Security practices

  • Server-side OAuth with PKCE and asymmetric (JWT) client authentication
  • Tokens encrypted at rest and never sent to the browser
  • Strict content security policy and an allowlist for outbound requests
  • Encrypted backups
